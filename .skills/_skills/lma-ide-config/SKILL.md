# LMA IDE Config

## When to use this skill

Load when the user wants to generate or update IDE/agent configuration files (Continue, Cline, or other supported targets) from the provisioned models in the database.

Also load (or run the sweep below) **automatically** whenever model inventory changes — see **Mandatory config sweep**.

## Mandatory config sweep

Run after any of these events (do not wait for the user to ask):

| Event | When to sweep |
|-------|----------------|
| **Model added** | After `add-model-from-yaml.py` and the base model is in Ollama (`ollama pull` / `ollama create`) |
| **Clone created or rebuilt** | After `ollama create <alias> -f …` and `ollama list` shows the alias |
| **Model or clone removed** | After `ollama rm` and DB cleanup (`is_active=0`, prune, or row delete) |
| **Role reassignment** | After `role_model` changes that add/remove provisioned clones |

```bash
./scripts/py scripts/sweep-ide-config.py
```

The sweep script:

1. Sets `provisioned_models.is_active` from `ollama list` (installed → `1`, missing → `0`).
2. Regenerates config for targets named in the resolved software profile (`lma_paths.py`: LMO sidecar or `computer-profile/software-profile.yaml`; `primary_agent`, `embedded_assistant`, `optional_agents`). Falls back to all supported targets if names are unset.
3. Writes repo copies under `integrations/IDE-model-management/<app>/`.
4. Deploys **Continue** to `~/.continue/config.yaml`. **Cline/Roo** stay in-repo — import via the extension UI (no stable global path).

| Flag | Purpose |
|------|---------|
| `--dry-run` | Print sync + generation + deploy actions without writing |
| `--no-sync` | Skip `is_active` sync from `ollama list` |
| `--no-deploy` | Generate repo copies only |
| `--target continue\|cline` | Override software-profile target detection |
| `--all-provisioned` | Include `is_active=0` rows (default: active only) |

**Agent obligation:** Parent skills (`lma-assess-import-model`, `lma-model-prune`, `lma-model-selection`, `lma-hf-gguf-ollama`) end with a config sweep when Ollama inventory changed. If clones are defined in the DB but not yet built in Ollama, run the sweep again after the user (or you) runs the `create_command` / `pull_command` values.

## Generate config only (manual)

When you only need repo artifacts without sync or deploy:

```bash
./scripts/py scripts/generate-ide-config.py --target continue|cline [--active-only] [--dry-run]
```

| Flag | Purpose |
|------|---------|
| `--target` | Which IDE/agent to generate for (`continue`, `cline`). |
| `--active-only` | Only include provisioned models where `is_active = 1`. |
| `--dry-run` | Print what would be written without writing files. |

Output goes to `integrations/IDE-model-management/<app>/` with role-appropriate timeouts.

## Supported targets

See `integrations/IDE-model-management/IDE.md` for:
- Per-app config locations and formats.
- Timeout recommendations by role.
- Manual setup instructions for apps not yet supported by the generator.

Config location docs for individual apps are at `integrations/IDE-model-management/<app>/config-location.md`.

## Other apps (manual)

For apps without generator support (Zed, Goose, Pi, OpenCode), follow the manual instructions in `integrations/IDE-model-management/IDE.md`. Ollama library `-mlx` tags are ordinary Ollama models and **are** included in the sweep. HuggingFace mlx-lm models (`runtime=mlx`) are not generated by `sweep-ide-config.py` — see `lma-mlx-lm`.

## Notes

- Generated config files under `integrations/IDE-model-management/*/config.*` are gitignored.
- `integrations/IDE-model-management/cline/provider-settings.json` is also gitignored.
- The generator reads `provisioned_models` and `models` from the DB.
- Prefer `sweep-ide-config.py` over ad-hoc `cp` — it keeps `is_active` and IDE paths in sync.
